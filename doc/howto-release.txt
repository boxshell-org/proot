Releasing PRoot (Termux fork)
=============================

This fork does not cut versioned releases.  Packages are built straight
from git by the termux-packages repository
(packages/proot/build.sh), so "releasing" means landing changes on the
default branch.  The checklist before merging anything user-visible:

Checks
------

+ Build on all four Android targets: aarch64, arm, i686, x86_64
  (`make -C src`).  A native Linux build is a useful smoke test but is
  not the shipping target.

+ `make -C tests check` — see tests/GNUmakefile.  Tests are bounded by
  TEST_TIMEOUT (default 120s); known failures live in XFAIL_TESTS and
  report as xfail.  A red suite means a real regression — only add a
  test to XFAIL_TESTS with a linked GitHub issue.

+ `make -C doc check` — the generated manual and man page must be in
  sync with src/cli/proot.h.  If you changed option text or the
  recommended binding lists, run `make -C doc` and commit the
  regenerated MANUAL.md and proot.1 together with the code change.

+ Exercise the change under a real guest rootfs (proot-distro works
  well) on a device, not only in the CI container.

Documentation
-------------

* Option names, descriptions, and the -R/-S binding lists live in
  src/cli/proot.h — that file is the single source of truth for the
  command line, and also produces `proot --help`.

* Prose (description, examples, caveats) lives in doc/proot.md.

* After editing either, run `make -C doc` and commit the regenerated
  outputs.

* If the change is user-visible, add a line to the "Termux fork"
  section of doc/proot/changelog.txt.

Historical note: the original upstream release process (OBS packaging,
Coverity scans, regenerating this CLI header from the manual via
docutils/xsltproc) was retired — see git history for the old workflow.
